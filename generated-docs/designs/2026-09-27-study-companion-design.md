# 学习伙伴：ChatGPT Projects 学习记录设计

日期：2026-09-27
状态：用户已于 2026-09-27 确认；进入实施计划阶段，未开始实现

## 目标与已确认的选择

用户继续在 ChatGPT 网页版现有 Projects 中提问和接受指导，不另建学习网页。以一个总 Skill 组织课程，根据资料建立课程知识体系，并随着学习积累个人疑问、知识联系及掌握证据。支持每四轮学习对话更新、手动更新和按日期查看记录，最终将可复用 Skill 上传 GitHub。

首个验证课程为 Aerodynamics。总 Skill 暂名 study-companion，中文显示名“学习伙伴”；名称可以替换，不影响数据结构。

保留用户此前的教学偏好：Lecture 定框架和深度，Textbook 补解释与适用条件，Tutorial 和教授考试提示提供应用要求及考试重点依据。主要中文讲解，保留英文术语；从物理意义、输入输出、假设出发，再展开推导和理解检验。

## 当前证据与能力边界

- 本地工作目录为空 Git 仓库，无现有应用、数据库、提交或远程地址。
- 当前 Codex 工具能列出 ChatGPT 项目及部分对话归属，也已成功读取“生成空气动力学学习技能”和“创建学习日志”历史内容。
- 已识别 Aerodynamics 项目 ID：[个人 Project ID 已省略]。项目名称改变时仍使用 ID 匹配。
- 旧对话提到了已生成的 Skill 和课程映射，但尚未读取这些原始附件；不得把旧回复中的权重或保存成功声明当成已验证事实。
- 尚未验证：项目上传文件的可用读取入口、网页学习对话的写入工具、每轮完成事件、网页能否持续读取最新学习状态。
- 仅安装 Skill 不会自动赋予后台监听、项目文件访问或 GitHub 写入能力。当前 Codex 的工具能力不视为网页端必然具备的能力。

## 分层与职责

1. 总 Skill：识别学习场景、选择课程、教学规范、调用存取工具及更新规则。规则保持精简，按需读取课程资源。
2. 课程知识库：课程资料索引、知识点、先修关系、考试依据。可以由数据库提供，也可以先使用文件；第一版先验证真实可访问的资料来源，不预设已有数据库。
3. 个人学习记忆：当前状态和每日增量日志，与通用 Skill 分开存储。
4. 同步工具：读取实际可访问的对话、去重、计数、持久化及导出。触发方式通过能力验证后确定。

课程目录是逻辑导航，不宣称在 ChatGPT 中新增原生二级菜单。用户可直接说“学习空气动力学”或在对应 Project 中学习。

## 学习模式

首次使用入口先收集专业和学习阶段（本科或研究生，研究生可注明硕士/博士）。只询问缺失项，不根据学校、课程难度推断。资料可通过“修改学习资料”更新；用于默认课程识别与讲解深度，不代表个人掌握水平。用户可拒绝填写并继续普通问答，但不创建已完成的学习档案或自动记录会话。

识别顺序：用户明确指令 > 已绑定 Project 加学习意图 > 专业内容加学习意图。单个专业词不足以触发，例如航空岗位邮件不算课程学习。相关数学即使没有航空术语，也可以结合上下文归入课程先修知识。

识别为候选学习场景时，询问一次是否开始记录本次学习。用户明确说“开始学习并记录”即视为确认。确认后持续记录本次学习，直到用户暂停或结束；拒绝后不对每个后续问题重复询问。切换课程时明确新的归属；跨课程问题确定主课程并保存关联。

Project 绑定只提供课程归属线索，不代表其中全部历史消息都应归入学习。项目设置讨论、闲聊、工具故障等不进入知识掌握记录。

## 首次生成课程知识体系

先列资料清单，检查可读性及覆盖范围，再构建 Lecture—Textbook—Tutorial—Exam 映射。来源包含文件标识、版本或内容摘要、页码/章节/题号；不可读的文件报告缺失，不补造内容。

每个知识点包含稳定 ID、英文术语与中文说明、核心概念、适用假设、先修知识、关联概念及资料依据。通用学科知识可以补充解释，但标注为补充，不能替代课程依据。

考试信息区分：明确考试分值、历年题统计、教师明确提示、教学优先级推测。没有足够证据时仅给优先级，不给虚假的数值权重。考试重要性与个人薄弱程度分别保存；提问频繁不自动提高考试权重。

## 增量更新

一轮是一次有效学习提问及其完整回答。工具调用、闲聊、重试和同一回答的重复读取不重复计数。第一版按课程和学习会话计数，各对话通过稳定标识隔离，避免交错消息混算。

累计四轮后处理尚未记录的内容，读取当前课程状态和相关知识点，不重读全部教材。用户说“更新学习记录”或“结束今天学习”时立即处理剩余轮次。手动更新成功后，已处理轮次不再计入下一批。

每批记录：具体疑问、误区及纠正过程、相关先修知识、已讲解内容、用户表现证据、待验证事项和下次起点。掌握状态使用“未验证、需要帮助、可独立解释、可独立应用”等有证据的描述；助手给出解释不等于用户已掌握。

以消息/轮次标识去重；如果来源缺少稳定标识，则能力验证阶段必须确定可靠替代策略后才能启用自动计数。以最后成功写入的位置作检查点，写入失败保留待处理内容，不推进计数。并发更新需串行化或检测版本冲突，避免覆盖。

## 日期与读取策略

每课程维护一份 current-state.md 和按 YYYY-MM-DD 命名的日志。同一天追加多次更新，保留时间、批次及来源；跨日批次按消息发生日期分配，另记处理时间。时区可配置，初始采用当前环境 Asia/Shanghai，不能仅凭专业或学校推断学习所在地。

日志记录变化，current-state 保存最新状态；纠正旧认识时保留更正关系，不静默抹除历史。下一次学习默认读取课程索引、当前状态和相关知识点，按需回看历史。

## 网页接入的实施顺序

第一步先完成端到端能力验证：从指定 Project 获取一段学习对话、访问对应课程原始资料、将摘要持久保存，并验证下一次网页学习能读取保存结果。

优先使用网页端可用的工具或插件进行显式保存调用；仅当已验证实际入口和权限后才采用。如果只能由 Codex 主动读取，则先提供手动“同步 Aerodynamics 学习记录”的工作流，明确其为手动同步。不能把“每四轮应更新”的文字规则描述成已实现的自动化。

后续若需要定时读取，通过用户明确选择的定时任务运行；定时同步只能承诺下一次运行处理已完成批次，不能承诺第四轮结束立即保存。浏览器扩展或独立后台服务属于后续可选范围，不在本次默默增加。

若网页不能直接读取最新持久记忆，必须提供并验证可用的项目资料更新/导入途径，说明是否有人工步骤；未完成回读验证前不声称实现跨对话记忆闭环。

## GitHub 发布

建议可复用 Skill、模板及同步代码存放发布仓库；个人日志和学习状态存放本地或独立私有仓库。课程原件与凭据不进入发布内容。公开或私有、目标仓库及最终名称在内容可审阅后确定；当前未选择目标仓库，不进行推送。

首版不内置当前用户的项目 ID、姓名、个人日志或机器绝对路径到通用发布包。项目绑定保存在个人配置中，发布包只提供配置格式及示例。

## 验收场景

- Aerodynamics Project 中的学习问题可以识别课程，询问一次记录意愿；闲聊和配置讨论不计数。
- 能依据已读原件建立课程映射；无考试证据时不生成虚假权重。
- 连续四轮只生成一批记录；手动保存两轮后不会在下次重复处理。
- 学习结束时保存不足四轮的内容；跨日和多对话来源明确。
- 写入失败后可恢复，重复同步不重复追加，当前状态与日志一致。
- 记录区分“已讲解”和“已验证掌握”，保留知识联系和来源。
- 新网页学习对话能通过已验证路径使用最新状态；若需人工步骤，流程清楚可操作。
- GitHub 待发布内容不含个人数据、原始教材或凭据。

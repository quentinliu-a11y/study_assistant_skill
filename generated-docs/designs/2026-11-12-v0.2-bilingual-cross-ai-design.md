# 学习伙伴 0.2 设计：双语、跨 AI、回顾入库（2026-11-12）

## 目标

一个可长期维护的学习 Skill：中文版和英文版都能单独安装；用户可能使用不同的 AI 助手；回顾和记录尽量由脚本执行，而不是依赖助手自觉；公开仓库只放通用内容。

成功标准：两个 Skill 文件夹各自完整可用；同一条规则只在一处定义；每日回顾的选题、去重和间隔由命令决定；没有工具的助手也能通过两段文本接续学习；现有 0.1 数据库和配置不需要手工迁移。

## 已确认的选择

- 双语：两个独立 Skill 文件夹，`study-companion`（英文）与 `study-companion-zh`（中文）。
- 范围：下列各节全部实施。
- 交付：新分支加 Pull Request。
- `ifm.md`：移到私有仓库 `study_assistant_logs`。
- 假设（未单独询问）：许可证用 MIT；`generated-docs/` 既有文件不动。

## 1. 目录与双语

两个 Skill 文件夹结构相同：`SKILL.md`、`agents/openai.yaml`、`references/` 六份、`scripts/`。脚本只在英文版目录维护，`scripts/sync.py` 复制到中文版，测试保证两份逐字节一致。测试还检查两版 Markdown 的标题、代码块、编号项和表格行数量一致，防止只改一边。

脚本的报错统一为英文（读者是助手）；`profile` 的交互提问和导出的 Markdown 按配置的 `language` 显示。0.2 之前的配置没有 `language`，视为 `zh`；新建配置默认为 `en`。

## 2. 规则只写一处

| 文件 | 负责的规则 |
|---|---|
| `SKILL.md` | 能力自检、八条核心规则、细则索引 |
| `references/teaching.md` | 建课、讲解模板、错题记录、考试模式 |
| `references/records.md` | 会话、计数、事件、掌握状态、日期 |
| `references/review.md` | 反复疑问、每日回顾流程、间隔 |
| `references/courses.md` | 配置、课程目录、课程专属规则、保密 |
| `references/cli.md` | 完整模式的命令和文件格式 |
| `references/portable.md` | 交接文件与会话摘要 |

README 只讲安装和用法并链接到这些文件。`START_HERE.md`、`templates/project-instructions.md` 和两份复习模板被取代后删除。

## 3. 回顾入库与间隔

数据库新增 `questions` 与 `reviews` 两张表。

- `question add`：新增疑问，或给已有疑问追加一次出现（日期加来源）。同一来源同一天只算一次；两个不同来源即为"反复出现"。
- `review pick`：每门课程每天一轮。已有当天记录时返回 `already_started`；否则按"反复且需要帮助 → 需要帮助 → 待验证 → 其他，同级取最久未问"选出到期题并记为已提问。`--again` 用于用户主动加练。
- `review mark`：`correct`（必须带用户原话）、`hinted`、`incorrect`、`skipped`。
- `review skip`：记录当天跳过。
- 间隔：连续答对后依次 1、3、7、14、30 天；提示后答出或答错则次日再问、连续次数清零、状态改为需要帮助；跳过不改变任何状态。

`export` 在存在疑问时生成 `recurring-questions.md` 与 `review-history.md`。目标目录里若有不带生成标记的同名手写文件，首次改名为 `*.manual-backup.md`，不覆盖。旧的手写清单需由助手用 `question add` 录入，脚本不解析自由格式文件。

## 4. 会话摘要导入

`import-session` 接受没有真实轮次 ID 的会话摘要（格式见 `portable.md`）。脚本以摘要内容的哈希生成线程 ID，条目存为带 `source_kind: digest` 标记的轮次，时间取摘要日期当地 12:00 起逐分钟递增，按四条一批提交。导出时注明"会话摘要，未经原文核对"。掌握状态为可解释或可应用时必须有用户原话。所有检查在首次写入前完成；同一摘要重复导入不产生变化（回顾结果按来源去重）。

## 5. 代码修正

- `export`、`review`、`import-session` 的时区取命令行参数，其次配置，再次 Asia/Shanghai。`batch_size` 从配置移除并被忽略。
- `turns` 表新增 `course_id` 列与索引；打开旧数据库时自动加列并回填。
- 更正事件在 `current-state.md` 中取代被更正事件，旧事件仍在日志中。
- Markdown 中事件 ID 显示为八位哈希加序号；`state` 仍返回完整 ID。
- 新增 `handoff.md`：下次起点、未掌握概念、回顾疑问及到期日、最近回顾日。
- 掌握证据的固定词表拦截改为"引文去除标点后至少 8 个字符"。

## 8. 跨 AI 兼容

按能力分三种模式，而不是按厂商：

| 模式 | 能力 | 记录方式 |
|---|---|---|
| 完整 | 运行命令、写文件 | 本地工具 |
| 项目 | 读上传文件，不能运行命令 | 读写 `handoff.md`，输出会话摘要 |
| 对话 | 只有对话 | 同上，由用户粘贴 |

- Skill 开头要求助手先自检能力并告知用户当前模式。
- `templates/starter-prompt.{en,zh}.md` 由 `sync.py` 从核心规则和 `portable.md` 的标记段落生成，长度上限 6000 字符，供项目模式和对话模式使用，同时取代旧的项目指令模板。
- `handoff.md` 的格式在导出器和 `portable.md` 中一致，是跨助手的通用接口。
- 规则正文不出现厂商名称；厂商相关的安装方式只写在 README 的表格里。
- 四轮计数等保证只在完整模式由工具强制，文档如实说明。

DeepSeek 网页版归入对话模式的依据是一条功能请求和第三方说明，未见官方文档，需实际试用确认。

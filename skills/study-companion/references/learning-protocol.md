# 学习记录协议

## 档案与会话

必填专业与阶段：本科 undergraduate；研究生 postgraduate；可细分 masters / doctoral。仅用户明确提供后保存，不由课程推断。只追问缺失项。profile 不完整或用户未确认本次记录时，不进入记录流程；普通答疑仍可继续。

session_id 指本次已确认的学习会话。明确结束后重新开始使用新的会话 ID；切换课程另建会话。暂停后产生的消息不计数。重新读取旧消息不能把未确认的历史聊天自动标为已授权学习；历史导入使用用户授权的指定范围。

## 计数

一轮 = 学习问题 + 完整回答。补充追问或用户对理解检验的作答及反馈都可计一轮；闲聊、配置、工具调用、失败回答、未完成流式内容不计。

按 course_id + session_id + thread_id 独立计数，四轮一批。手动更新和结束学习 flush 尾批；成功提交后清除该批待处理状态。多对话可汇入同课程，但不混成一次四轮会话。

只导入可验证的时间和稳定消息 ID。重复读取去重，已完成消息被编辑则报冲突，先人工核对所需分支，不默默覆盖。采集时间不冒充原消息日期。

## 更新内容

每条事件记录：来源轮次、概念 ID、具体疑问、讲解状态、掌握状态与用户作答证据、相关概念、可选更正指向。所有批次轮次都应由事件覆盖；没有新增理解时如实写“已复习，未新增掌握证据”。

掌握状态：unverified / needs_help / can_explain / can_apply。后两项必须附用户原话片段及该轮次引用；“好”“懂了”、助手自己的答案和提问次数均不足以证明。

提交时完整保存该批事件与下次起点，课程版本检测防止覆盖另一条对话刚保存的变化。冲突时重读当前状态、保留新增内容再合并。

## 归档

默认 Asia/Shanghai，用户可以明确修改；按原消息日期归档，一批跨日按事件引用的轮次日期拆开。保存处理时间与来源日期，勿将今天的补同步写成今天的学习。

数据库是本地记录源；Markdown 是可重建导出。更新以增量事件为主，current-state.md 汇总各概念最新事件及待验证问题，logs/YYYY-MM-DD.md 保留历史。同日多批不覆盖。更正保留 correction_of 与旧事件。

## 实际保存能力

- 工具可写：调用 CLI，检查返回结果，导出并回读。写入失败不推进计数，导出失败可以重试。
- 网页无工具：生成学习状态和按日摘要，明确“尚未写入外部存储”；用户保存或交给有工具的助手同步。
- 同步下一次网页学习：将最新 current-state.md 提供给对应 Project/对话，并用其中真实的“下次起点”验证回读。上传 GitHub 不会自动完成此操作。

# 反复疑问与每日学习前回顾

## 文件与读取

每门课程维护 `recurring-questions.md`（疑问清单）和 `review-history.md`（按日期的提问与作答记录）。本地配置存在时，文件放在该课程的 `resource_dir`；私有笔记仓库中与课程 overview.md 同目录。跨设备先读取最新文件，写入前重新核对，保留双方新增记录。文件未提供或不可读时明确说明；不要宣称已同步或已检查今天是否复习。

两份文件由学习助手直接维护，是独立于数据库的个人资料。现有 CLI 只生成 current-state.md 和按日问答日志，不会生成、统计或更新这两份文件。备份时同时保留数据库和这些 Markdown。不要手改生成的 current-state.md 来存放长期复习进度。

## 记录哪些疑问

- 记录用户明确说不理解的现象、错误解释，以及后续仍未通过验证的具体困惑。仅问某个主题不等于已经误解；一般性的“尚无作答证据”标为待验证。
- 同一个根本困惑使用稳定问题 ID，保留每次独立提问或错误作答的日期、可核对来源和简短原话／忠实转述。同一轮被复制到日志、状态、回顾中只算一次；重新导出、整理或助手再次提问不增加出现次数。
- 至少两条独立来源支持相同困惑时标记“反复出现”。同主题但不同子问题注明“相关追问”；仅一条来源也可作为“尚未理解／待验证”候选，不能虚构频次。来源不足时写“次数待核实”，保留证据缺口。
- 每项保存：问题 ID、具体现象与困惑、概念及先修联系、首次／最近出现日期、来源清单与去重依据、当前状态、最后回顾日期、可用于提问的短问题、下一步。
- 状态使用“待验证／需要帮助／可独立解释／可独立应用”。只在用户实际作答足以支持时升级；保留原话、日期和来源。一次答对后降低近期优先级，后续换情境验证；再次答错保留旧证据并更新为需要帮助。

每四轮、手动更新或结束学习时合并新增疑问，保留历史来源。不要每次全量重写 Skill，也不要把维护文档的操作计作学习。

## 每日开始时如何问

1. 已确认开始学习后，用用户配置的时区确定当天日期（默认 Asia/Shanghai）。检查当前课程 review-history.md：当天已有已提问、已完成或跳过标记，则继续已有进度；不自动另开一轮。同一天切换到另一门课程时分别检查。用户明确要求再练可以追加。
2. 从未解决的问题选 1–2 项：优先反复出现且需要帮助的困惑，再选未理解／待验证项；同等条件优先较久未问、与今天内容有关的项。轮换题目，不每天机械重复同一句；只剩一项时问一题，无候选时直接开始新内容。
3. 只呈现短问题和必要条件，先让用户解释现象、比较条件或作简短推导；不要同条消息先给出答案。可以一次列两题，也可以逐题问。不要把一个题号拆成大量子题。
4. 实际提问后记录当天、课程、问题 ID、所问原文和“已提问，待作答”；选好的草稿不代表已问。用户跳过时记“跳过”，继续学习且不降级掌握状态。保存失败时说明并保留当前对话进度，不能声称跨对话去重已生效。
5. 根据实际回答区分独立回答、提示后回答、仍需帮助、未作答。先指出理解正确和遗漏之处，再给有针对性的解释；需要时用一个变式检验。只记实际发生的作答，不预填成绩。完成后接回原来的学习起点。

只有实际完成的回顾问答才按原协议计入四轮；发题、跳过、未回答不单独算一轮。与其他学习事件使用同一来源去重，不能同时当成两个新事件。

## 网页、导出和同步

无文件工具时提供两份 Markdown 的增量更新或可保存文本，明确尚未写入文件。同一对话用可见标记避免重复；跨对话需要用户提供最新记录。触发点是用户开始学习，不是定时提醒或后台主动发消息。

个人疑问、原话和复习历史仅同步至用户指定且确认私有的目标。公开 Skill 只保存规则与空白模板。记录维护日期和原始学习日期分别写明，不能将历史整理伪装成今天的学习。
